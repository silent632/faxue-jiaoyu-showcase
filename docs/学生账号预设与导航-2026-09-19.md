# 学生账号预设与导航调整

## 使用方式

- 左侧“交流与资料”是独立区域，提供交流专区、资料专区和场景研习；资料尚未提供时，资料页明确显示暂无可下载内容。
- 左下角固定显示账号入口；登录后按实际权限显示教师工作台、管理员后台及账号与退出。手机端在导航抽屉底部，紧凑阅读模式保留简短账号按钮。
- 学生账号为完整学号，初始密码为学号后六位。姓名与班级按名单预设，不提供公开姓名下拉列表或自主选择管理员身份。
- 首次登录需设置至少12个字符的新密码；设置后重新登录。改密前服务端仅开放登录状态、改密和退出，不开放学习或社区API。

## 名单与边界

本次收到六份文件，共729条记录。一个学号对应不同姓名，隔离这两条记录后，可处理727条无冲突记录。冲突具体位置已反馈用户，等待正确学号；不得选取其中一人覆盖另一人。

原始表格与提取结果保留在用户提供的名单目录中，不进入代码仓库。仅提取学号、姓名、班级。账号准备目录权限为700，JSON文件为600；不提取住址、电话等无关字段，不生成明文密码清单。

这批账号仅预设到本机D1。正式站仍待Cloudflare授权恢复、目标库绑定和迁移验收；本地账号可用不等于线上已经开通。不得上传本地测试库整体替代正式库。

## 维护命令

准备清单需要 Python 和 openpyxl：

```bash
python3 scripts/prepare-student-roster.py '<名单目录>' '<仓库外的私有输出目录>'
```

输出 `students.json` 与 `roster-review.json`；前者仅包含可导入字段，后者记录冲突来源。输入文件只读，不修改原表。

本地预设：

```bash
npm run db:migrate:local
node scripts/import-students-local.mjs '<私有输出目录>/students.json' '<本地管理员账号>'
```

脚本拒绝代码仓库内的清单和非本地专用配置，跳过已存在的账号，不重置密码、不修改既有角色。按25人一批处理，并记录创建审计。密码使用独立盐值哈希，临时SQL只含哈希，完成后删除。

新增迁移 `0010_initial_password.sql`；认证、会话接口及健康检查需要该迁移。部署时先在独立预览库应用迁移，再核验初始凭据、改密前访问拒绝、改密后登录、旧会话撤销和重复导入。

## 验证

`tests/server/identity.test.mjs` 使用虚构学生验证预设、重复导入、首次改密、旧密码拒绝及真实浏览器流程；截图使用虚构测试数据。原站核心及浏览器回归另行执行。真实名单导入后的验收只输出汇总数量，不打印学生凭据。

本轮执行结果：本地创建727个账号、16个班级小组；回读与名单匹配727条。再次执行导入新增0个、跳过727个，727个账号保持首次改密标记。抽查3个实际账号初始登录、姓名、身份与访问限制通过，抽查不修改其初始密码。测试结果为177项核心、32项原站浏览器、20项服务测试通过；最后补充的导航高亮浏览器验证通过。截图及不含学生明细的验证汇总位于被忽略的 `output/verification/`。
