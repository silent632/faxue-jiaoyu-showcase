# 裁判文书研习平台：系统性优化方案

版本：1.0｜制定日期：2026-09-06｜状态：实施中，逐项进展及验证见 `PROGRESS.md`。

适用项目：`/Users/silent/Projects/faxue-jiaoyu-yanxi`。

依据：2026-09-06 本地深度审阅、日期对照与基线验证。历史原始日志存放于本地 output/；可随仓库复查的最终结果见 [优化验收与交接](优化验收与交接-2026-09-08.md)。

本方案将已发现的问题转成实施顺序、工作包和验收条件，不表示修复已经完成，也不包含发布授权。

## 一、优化目标与边界

目标是使平台达到“材料可核对、记录可恢复、任务可完成、反馈能指导修订、更新可验证”的实际教学使用标准。

保留现有 Next.js 静态导出、结构化内容和本地学习记录的基础。优先做局部完整改进，保留案例 ID、课程 slug 和已有入口，保护浏览器旧记录及工作区未提交改动。暂不扩展账号、班级管理、云端同步、在线教师批改或自动生成式评分；这些需要独立的产品方案。

采用三条贯穿各阶段的规则：

1. **有证据再改数据。** 自动抽取结果是候选值；案号年份只能提示异常，不能推导裁判日期。仅核对日期不能把整篇案例标为“已审核”。
2. **内容保存与任务完成分开。** 随时保存草稿；完成状态必须满足模块要求；完成要求只证明产出齐备，不证明法律结论正确。
3. **按用户行为验收。** 测试数量、页面数量、代码行数不作为优化成功指标；必须验证恢复、完成、筛选、原文定位和修订等具体行为。

上一轮基线为：210 篇案例、8 期课程、6 个实验模块、127 项测试通过、580 页静态构建成功。82 条 PDF 日期差异属于自动提取对照结果；其余 128 份未被该规则识别，不应被默认视为正确。基线数字在实施开始时轻量核对，后续按真实变化更新。

## 三、工作包

### W00：固定基线、记录契约和验收样本

**范围。** 保留已有工作区改动；记录当前提交和配置；建立小规模回归样本及问题编号，沿用本次报告证据。测试使用独立本地浏览器来源或隔离上下文，不操作用户的线上学习记录。

**实施内容。**

- 为日期差异、零字实验、快速离开、存储失败、第三页深链和 375px 布局固定可重复步骤。
- 明确案例字段审核、实验 draft/completed 状态、记录版本和迁移规则；先写少量契约测试，再修改调用方。
- 为后续每条问题记录“待处理/处理中/已验证/待证据”及验证依据，不用一个总勾选覆盖所有数据。

**交付与验收。** 实施清单、失败样本、记录格式约定；原有内容和学习记录可保留，已知缺陷在修复前能稳定复现。不开设新的复杂测试平台。

### W01：案例元数据校准与证据分层

**主要落点。** `data/generated/cases-extracted.json`、`lib/showcase-cases.js`、`lib/content/validate-content.js`、相关数据脚本。

**实施顺序。**

1. 将现有 82 条差异转为候选修订记录：caseId、字段、旧值、候选值、原文件、页码、原文片段、核对结果。
2. 核对明确标注的审结日期及正文落款，同时确认属于当前案号和当前程序；存在冲突时保留冲突信息。
3. 对未识别的 128 份采用正文落款、必要的 OCR 或其他可靠原始依据；同轮处理 6 条缺失值。结果分为确认、原文缺失、来源冲突、无法识别，不用推测值填满。
4. 接着核查案号、法院和规范引用；精选教学案例进一步核查事实、争点、说理与标签。
5. 排查日期抽取是否错误命中事实时间，修复可定位的生成入口；若旧抽取器不在项目中，建立受检验的导入步骤，明确历史来源不可追溯部分。

**数据约定。** 保留现有案例 ID 和展示接口；审核记录用最小的旁侧结构维护，例如 `content/case-evidence.json`，键为 caseId。按字段记录核对状态，原文摘录与教学整理使用不同字段。维护来源版本或文件指纹；来源变化后相应引用进入待复核状态。不要复制整个案例库形成两套互相竞争的数据。

**展示策略。** 未核对的日期不作为精确推荐依据；缺失日期排序放入明确的未知组。原文仍可阅读，未经审核的材料不作为“标准答案”。不能因旧 status 全部待审核而直接下架 210 个稳定入口。

**验收。** 210 篇均有日期核查结论；82 条差异逐项销项或保留具体阻碍；每个写入的新值都有页码/片段依据；无静默猜测；日期筛选、排序和导出使用相同数据。

### W02：统一草稿保存与失败反馈

**主要落点。** `lib/study-workspace.js`、`lib/experiment-archive.js`、`components/use-study-workspace-draft.js`、`components/experiment-shell.js`。

**实施内容。**

- 统一写入返回值，例如 `{ ok, savedAt, errorCode }`；只有成功才更新“已保存”状态及保存时间。
- 针对小体量文本与结构化输入，优先在更新时同步写入最新记录，避免“停止输入 3 秒才保存”的空窗；如测得明显输入阻塞，再引入有最大等待时间的合并写入，并保留导航前立即落盘。
- 研习与六类实验均支持自动草稿；在关键站内跳转、失焦、页面隐藏等时机补充保存。退出事件只作补充，不作为可靠性的唯一保障。
- 存储失败时保留当前内存内容，显示具体可恢复状态并可导出；保存失败不能自动标为完成。
- 记录包含版本与修订标识。监听跨标签页变化；发现本地有未保存修改与外部新版本冲突时保留两份或提示选择，不静默覆盖。此次不承诺协同编辑能力。

**验收。** 输入后立即站内跳转再返回仍保留；常规刷新恢复；禁用持久化、容量不足和损坏记录有明确反馈；单条损坏不使档案全页失效；成功提示与实际落盘一致。

### W03：六类实验完成条件与旧档案兼容

**主要落点。** `lib/learning-loop.js`、`lib/experiment-archive.js`、六类 `exp-*` 组件、实验进度、首页与档案统计。

统一使用模块级完成检查，返回缺少的具体内容；组件提示、阶段跳转、存档完成和档案计数调用同一规则，避免各自判断。

| 模块 | 最小有效产出方案 | 不应被当成完成的情况 |
|---|---|---|
| 推理构建 | 规范前提、事实对应、结论及一项涵摄反思齐备 | 只点选一条素材 |
| 争点论证 | 双方论证达到现有输入要求，并形成自己的判断 | 只写一方或只打开判断面板 |
| 规范检索 | 选择规范、说明选择理由、完成可用参考材料对照 | 只勾选；参考材料缺失 |
| 法律解释 | 三种解释路径有内容，并选择方法、说明理由 | 任一字段变化即通过 |
| 价值衡量 | 两侧价值、各自理由、衡量取舍与结论齐备 | 只拖动滑块 |
| 文书批注 | 在可追溯原文上完成标注，并填写整体评价 | 只点选标签；无原文可批注 |

以上是结构完整性要求，不宣称自动判定论证正确。保留自评作为独立信息；不要求学生必须给高分才能完成。字数只提示投入程度，不新增更多无依据的字数门槛。

**状态规则。** 草稿可随时保存；检查通过后用户完成任务，才赋予当前版本 completed 状态。修改后若不再满足要求，当前版本回到草稿；保留首次完成时间作为历史信息，统计按当前有效状态计数。教学质量评价单独展示。

**迁移规则。** 不删除旧记录，不把 completedAt 自动等同于达标；可验证的旧产出按统一规则重新计算，缺少关键字段的保留为“历史记录/待补全”，不计入当前完成数。迁移前保留原始序列化内容，完成后校验；空间不足则中止迁移、保留旧数据并支持导出。迁移重复执行不应增加副本或损坏内容。

**验收。** 零字存档不计完成；六模块均有有效与无效样例；侧栏、首页、档案及闭环计数一致；旧记录内容完整保留；空旧记录不继续计完成。

### W04：规范检索的参考数据与比较机制

**主要落点。** `components/exp-norm-retrieval.js`、`lib/experiments.js`、案例规范字段、内容校验及模块配置。

- 为参考规范建立稳定标识，分开名称、别名、版本、条文及原文位置；按标识比较，取消宽泛的名称包含判断。
- 以核对后的参考规范配置候选池，并补充有教学意义的干扰项；界面不通过选项顺序或标记直接泄露参考集合。
- 处理历史名称与现行名称时区分任务目的；新增“其他依据”可录入说明，但不默认判错或判对，标记为待讨论的补充依据。
- 对照结果区分“与材料援引一致”“材料另有援引”“提出补充依据”，不把未被法院援引自动等同于不能适用。
- 案例没有可靠规范数据时，保留原文入口但不提供可计完成的规范对照任务；提示选择其他可用模块。

**验收。** 对当前 75 篇候选案例逐篇核对可用性；39 篇的 81 条不可匹配记录均有修正或有依据的排除结论；每个启用任务的参考项均可表达；空参考集无法生成误导性的命中/遗漏统计。

覆盖首页、案例列表/详情、课程入口/详情/材料、实验入口及六模块、研习工作台、档案、视频。使用 375、390、768、1280px 和明暗两种模式；先查所有页面类型，再抽查内容边界样例，不必为同模板的 210 个案例重复保存截图。

交互补齐输入标签、选中状态、星级按钮名称、批注键盘操作、导航抽屉焦点管理和焦点恢复。PDF 主动缩放可以在阅读容器内滚动，不允许把整个页面撑宽。

**验收。** 外层页面无非预期横向滚动；标题、操作区不裁切；长内容可读；六模块可用键盘完成；暗色下提示和选中状态可辨认；保留修复前后截图。

### W06：分页、续学与推荐统一

**主要落点。** `components/cases-workspace.js`、`components/home-continue-card.js`、`lib/learning-loop.js`、`components/archive-workspace.js`、导航统计。

区分首次 URL 恢复与用户主动改筛选条件，避免首次防抖重置页码。保留前进/后退恢复，过滤后才对超出范围的页码作合理收敛。

推荐统一采用以下次序：优先最近编辑的未完成任务；其后补全同案例缺少的研习或实验；再提供当前课程后续任务；都已完成后推荐新的能力练习。首页续学比较研习和实验的实际更新时间，直接返回对应任务。旧闭环状态与新状态使用同一计算入口。

**验收。** 第三页深链与刷新保持第三页；切换关键词合理回到第一页；浏览器返回恢复预期筛选；部分研习、仅实验、完整闭环和零记录都有确定且解释得通的下一步。

### W07：JSON 导入恢复与冲突处理

**主要落点。** 档案页及共享记录读写层。

增加导入预览，展示可导入、重复、冲突、未知案例和版本不兼容记录的数量。校验结构、类型和合理文件大小，不把输入文本作为 HTML 执行。重复导入保持幂等；冲突默认保留本地和导入两份可恢复数据，不用“最后时间更晚”作为静默覆盖依据。

导入先验证再提交；提交失败保留导入前记录。未知案例记录可存为历史文本档案，不生成不存在的学习链接。继续兼容已有 version 1 导出。导出前使用最新可读记录，避免跨标签页导致陈旧导出。

**验收。** 导出后在新的隔离浏览器中恢复相同内容；重复导入不倍增；坏 JSON、未知版本、写入失败均不破坏原数据；迁移前的导出文件仍能读取。

### W08：原文摘录、批注与 PDF 定位

**主要落点。** 原文证据内容、`components/exp-annotation.js`、`components/pdf-viewer-inner.js`、研习材料阅读区。

精选案例先建立带稳定 ID、页码、原文文本和来源版本的摘录。批注主材料使用真实裁判说理，教学重述单独展示；标注保存段落 ID 及来源版本，不再仅存数组下标，以免资料调整后标到其他段落。

PDF 先增加可用的文字选择层和页码跳转，并让引用入口定位到对应页；再补文档内查找。复制时附带案号与页码。扫描型 PDF 的不可选择状态需明确，不把 OCR 自动识别当成已核对原文。确认 worker 与依赖版本一致。

**验收。** 精选案例摘录逐条对得上原 PDF；点击引用到达对应页；重排摘录不改变标注目标；来源版本变化时提醒复核；原有翻页、缩放和下载保持可用。

### W09：精选案例评价量规与修订记录

第一批默认选 8 篇，优先每期课程一篇，并共同覆盖六项能力；若课程覆盖与能力覆盖无法同时满足，可扩到最多 12 篇。入选条件是原文可核对、任务明确、规范有依据和具有代表性，不按最早日期自动指定。

每篇交付：案例级任务、理论视角检查点、实务视角检查点、参考分析、常见错误与修订要求。量规先验证材料依据；不能从模板生成即标为教师审定。固定模块提示明确作为“对照指引”，只有存在相应审阅记录才使用“教师点评”等表述。

保留初稿与修订稿及修改说明，分别展示结构完成、学生自评和有出处的评价意见。第一批采用可审核的静态量规和对照，不引入自动生成式打分。

**验收。** 每篇有具体而非重复通用提示；学生能说清修改了哪一点及依据；完成后的输出包含原文引用、初稿、修订稿和反思；自评不被呈现为客观能力分。

### W10：八期课程任务卡与进度衔接

**主要落点。** 八份课程 JSON、课程详情、学习记录及首页推荐。

每期增加简短任务卡：学习目标、先修提示、投入参考、主案例、指定实验、产出、评价入口。投入时间以教学判断标为参考，不伪装成实测。教师观察、分工、互评等材料进入次级区域，不删除原链接。

课程完成由指定学习产出计算，不以打开视频或浏览页面判完成。对真实案例与假设情境作明确区分；资料不足的真实案件不编造案号。课程任务发生版本变化时保留历史完成记录，并展示新要求，不悄悄覆盖学生成绩。

**验收。** 八期都有清楚的起点、产出和下一步；课程→案例→实验→修订→档案→续学全链路可操作；原教师材料仍可访问。

### W11：自包含内容构建与资源可用性

**主要落点。** `lib/course-package.js`、内容加载器、`scripts/audit-assets.mjs`、`package.json` 及真实托管构建配置。

梳理构建必需输入，将已核对且可入库的课程内容形成带版本的快照。开发预览可使用明确 fallback；正式验收必须列明实际使用的输入和缺失项。避免同一提交在两台机器静默生成不同课程。不要在尚未比较差异前删除回退内容。

把本地资源审计与远端可用性检查分开：前者检查文件、链接和类型；后者记录访问状态、重定向和媒体响应，必要时使用小范围读取，不下载整段视频。单次临时网络失败记录为待复检；持续不可用的资源需提供可用替代或明确状态。

提供 out 目录静态预览脚本。只读核查 Cloudflare 实际构建命令、环境与发布门槛，将建议配置写入交付，不因本方案自行触发线上发布或改权限。

**验收。** 新目录安装后可用声明的输入构建；已核对内容一致；依赖缺失不会被伪装成完整发布；远端检查结论可复查；本地静态预览工作正常。

### W12：内容负载、样式与页面信息

**主要落点。** 案例/课程列表数据模型、`app/globals.css`、实验工作区、动态页面 metadata。

- 案例列表只传筛选与展示所需字段，研习参考文本留在对应页面；课程列表不传完整材料对象。先测是否改善，再决定是否进一步切分。
- 记录优化前后未压缩大小、压缩传输大小及同条件页面加载；以相对变化评估，不能只看 First Load JS。计划目标为案例列表未压缩 HTML 至少减少 30%，保持检索与筛选结果完全一致；若有效字段使目标不可达，报告字段成本与实测结果，不能删功能凑指标。
- CSS 按页面责任整理，合并重复暗色 token；仅删除确认无引用且非动态拼接使用的类。优先抽出实验保存和完成判定，避免大范围重写。
- 补充案例、课程标题和描述、规范链接及站点地图；旧别名路由保持兼容。站点正式域名以实际配置核对。

**验收。** 列表传输减少且功能不变；主要页面视觉无回归；原链接可用；动态页面标题可区分；不以减少代码行数作为验收。

### W13：分层测试与最终检查

贯穿 W01—W12，不留到最后统一补测。

- 数据测试：结构、ID、规范引用、来源位置、候选项覆盖；一致性规则触发核查，不替代人工或证据判断。
- 纯函数测试：完成规则、推荐、迁移、导入合并、过滤条件；包含失败路径与幂等性。
- 浏览器测试：真实保存/恢复、失败提示、零字完成拦截、阶段推进、分页恢复、闭环、导入及关键移动端布局。
- 保留有用的文案守卫；逐步替换没有行为保障的源码字符串断言，不为了测试数量增长添加重复测试。
- 每个工作包跑相关检查；涉及页面生成、路由与资源时构建。综合交付执行完整 check 和核心浏览器回归。原有失败与本次新增失败分别记录。

**验收。** 已发现的行为缺陷均有对应回归；不能靠改期望、跳过用例或删测试制造通过；完整检查日志与截图可追溯。

### W14：文档、指标与交接

更新现有 PROGRESS、CLAUDE、CONTENT_MAINTENANCE 和 content/README，使内容拥有者、实际命令、已完成阶段与真实代码一致。本方案保留为版本化计划，进度只在 PROGRESS 维护，避免两处手工维护任务状态。

案例数和课程数从实际内容生成；使用者、视频播放、回访率补统计区间、来源和口径。拿不到指标原始证据时标为待核验，提出隐藏或改写相应公开数字的具体方案，不猜测、不把本地计数替代线上统计。

不整理或修改用户的全局记忆；不处理与本任务无关的文件。最终交接包含已完成工作、验证证据、未决材料、兼容变化及恢复办法。

**验收。** 新会话仅凭项目文档即可找到正确入口；不再保留已过时的 579 页/122 项或个人路径清理待办；公开指标均有明确证据状态。

## 五、实施与回退规则

按工作包形成小批次改动，避免一次混合修改案例数据、存储格式和全站样式。相关文案改 content，结构变化改组件，计算规则留在 lib；仅在现有文件不足以承载清楚职责时新增文件。

案例数据修订保留字段级旧值和证据；禁止重排生成新的 caseId。浏览器记录迁移先保留旧内容、验证新格式再切换；升级中断仍能回到旧记录。代码回退时应能识别或导出新格式，不能让用户记录因版本回退变得不可读。原文版本变化保留旧引用信息，不能覆盖后导致历史批注失去对象。

每个阶段交付：改动范围、影响页面、完成的验收编号、日志/截图、未决证据和兼容说明。常规检查与修复连续推进；确实需要外部材料时只提出具体缺口，不泛泛要求用户重新整理全部资料。
