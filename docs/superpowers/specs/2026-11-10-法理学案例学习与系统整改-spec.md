# 法理学案例学习与网站系统整改 Spec

版本：1.0｜2026-11-10｜状态：设计与验收基线，尚未实施。对应项目 `faxue-jiaoyu-showcase`。执行前重新核对代码与线上状态；本文件记录设计，不将规划写成已实现。

## 1. 目标与范围

面向刚学完法理学的大一学生，同时保留其他年级与匿名学习者的使用方式。将知识图谱、案例检索、原文阅读、研习工作台、实验、交流及教师反馈连接，形成“课堂知识 → 案例理解 → 法理分析 → 练习表达 → 交流反馈 → 回顾深化”的学习路径。

本 Spec 同时覆盖已识别的账号、场景、教师与交流、测试发布及内容治理待办。既有案例 ID、URL、匿名学习、本地记录、导入导出、任务与脚本历史版本均须兼容。暂不接入学校统一身份、教务、正式成绩，也不虚构未提供的资料、教师信息或案例事实。

## 3. 用户与权限

| 用户 | 能做什么 | 权限边界 |
|---|---|---|
| 匿名使用者 | 浏览公开知识点、案例、原文与开放实验；本机记录、导出 | 不得访问课程私有数据或发帖 |
| 学生 | 登录后使用个人任务、提交及授权的讨论 | 本人草稿默认私密；改密前只允许本人状态、改密、退出 |
| 教师 | 管理授权小组的任务、查看已提交内容并反馈 | 不得读取其他小组或未提交草稿 |
| 实务导师 | 阅读和回复被授权范围的任务或讨论 | 撤权立即生效，不自动获得教师或全站权限 |
| 管理员 | 管理账号、授权、场景发布、交流治理与审计 | 变更须审计；不得移除最后有效管理员 |

具体权限以服务端判断，不依赖前端隐藏。任何从案例、知识点或任务带入讨论的链接都不能扩大源资源权限。

## 4. 信息架构与用户流程

保留现有案例库入口，新增清楚可见的“按法理知识找案例”入口，使用“章节 → 知识点 → 案例”分层列表；普通案件检索仍可独立使用。案例详情中新增简洁的“关联法理知识与阅读问题”，并保留案例事实、争点、结果、原文与现有学习入口。

| 起点 | 系统行为 | 下一步 |
|---|---|---|
| 知识章节 | 展示经复核的知识点、简短提示及可用案例数量；无案例时明确提示 | 选择知识点进入案例列表 |
| 知识点 | 展示概念定位、相关案例及可核验的推荐理由；不展示未审核关联 | 进入案例阅读，或回到原有筛选 |
| 案例检索 | 保留关键词、案由及原有条件；增加可组合的知识点筛选、清除与 URL 恢复 | 结果显示关联主题和阅读入口 |
| 案例详情 | 按已审核关联展示阅读问题和文书依据；注明导读不等于唯一答案 | 阅读原文、进入研习或对应实验 |
| 研习与实验 | 传递案例 ID 和知识点上下文；返回路径可恢复 | 本机保存、导出，或已登录者使用授权任务 |
| 交流 | 登录者从案例/知识点发起讨论，关联标题及可访问链接 | 提问、回答、追问、治理；私人资源不泄露 |
| 教师任务 | 教师选择可用案例、知识点及任务要求 | 学生保存与提交分开；教师只看授权范围内已提交版本 |
| 资料 | 保留入口，按明确来源和授权整理材料 | 有材料后按主题连接；无材料显示真实空状态 |
| 场景 | 在批准开放的版本中提示知识点和学习任务 | 保留版本及产出；场景未开放时准确提示 |

页面一次突出当前学习问题和一个主要下一步，其他关联作为次级入口；移动端与键盘可操作，知识点解释避免大段说教。法的起源或学派等不适宜直接对应单篇裁判文书的内容，允许仅显示背景与问题，不强造案例关联。

## 5. 知识与案例数据契约

新增结构化内容文件及通过 `lib/content/` 的加载器，实际命名随仓库约定确定；知识图谱图片只作输入来源，不进入运行期强依赖。

1. **章节**：稳定 `id`、名称、顺序、来源图片、复核状态。
2. **知识点**：稳定 `id`、章节 ID、名称、别名、简要说明、父子关系、来源图及复核状态。图中遮挡内容标为待核，不猜填；允许同义词映射，不合并语义不同概念。
3. **案例关联**：案例 ID、知识点 ID、关联类型（裁判明确讨论／适合分析的观察角度）、推荐理由、阅读问题、证据来源及页码或可定位段落、复核状态和复核人/日期。观察角度不得伪装成法院明确采用的术语或结论。
4. **发布状态**：候选、待核、已复核、撤下；只有已复核关联进入公开筛选与推荐。原文缺失、定位不可靠或案号有疑点时不生成肯定性关联。
5. **兼容**：现有实验推荐标签继续独立维护；新旧标签可通过明确映射共存，保留实验推荐行为。构建校验 ID 唯一、引用有效、状态合法、公开关联证据非空，报告不输出学生数据。

首批优先处理法律关系、法的价值、法的渊源与效力、法律责任、法律方法；采用少量真实案例试点，具体数量以有原文依据和教师复核结果为准，不为凑覆盖率编造。每个公开关联须能回到相应文书依据。教师/内容负责人审阅是教学结论的发布条件；工程自测不替代审阅。

## 6. 场景、交流、教师与资料

- **场景**：现有听证脚本未开放、未完成教师审阅。先在隔离预览中核验角色、节点、版本、保存恢复及任务关联；经内容负责人审阅并确认开放方式后发布。场景体验加强分为可交付的叙事、视觉、交互改善与另行设计的 3D 技术方案；不得把已有页面称为已实现 3D。允许低性能设备使用等价路径。
- **交流**：复核现有发帖、回答、追问、举报、隐藏、恢复和授权；为关联知识点/案例添加带权限校验的引用。明确隐藏回答对作者本人、普通用户和管理员的身份显示，保留管理员审计。
- **教师**：在测试数据中验证建组、授权、布置、提交、点评、修订、撤权与跨组隔离；真实教师及导师账号按实际人员信息配置。统计注明时间与口径，不呈现未经同意的个人草稿。
- **资料**：材料未提供前保留真实空状态；收到后核对来源、授权、隐私及适用时间，建立标题、类别、来源、日期、知识点关联和撤下流程，不能将经验贴作为现行规则或官方结论。

## 7. 存量账号安全与运行保障

**激活方案推荐**：为待激活学生签发独立随机一次性凭据，经可信渠道私下发放，服务端只保存哈希并限制有效期；使用成功后设置个人密码，签发和重签发均留审计。实现前落实分发渠道与切换安排。

迁移须保留用户 ID、角色、组别、既有提交与记录；已设置个人密码的账号不得批量重置。区分待激活、已激活、需人工核验等状态；不得仅凭改密标记认定身份真实。激活凭据的消费、密码设置及并发竞争采用明确的原子语义；过期、重签发和改密撤销旧激活会话。提供无法收到凭据或疑似被抢登的人工核验和恢复路径。生产切换前准备可审阅的影响范围、备份、演练及回退；不在公开仓库或日志保存名单及明文凭据。

登录、错误密码、不存在账号、改密及并发请求须在独立环境测量实际 CPU、延迟、错误率和限流；记录计划、工具、样本和日期。不得仅因免费套餐预设降低散列成本或使用未经评估的密码算法。限流覆盖账号、来源与共享校园出口，防止一个来源消耗其他人的账号额度；处理会话及限流数据时保留过期和撤销语义。

## 9. 可执行验收

1. **知识点**：至少完成一条“章节 → 已复核知识点 → 已复核案例 → 原文依据 → 阅读问题”的真实路径；支持返回、刷新和筛选 URL；空结果有提示，待核数据不公开为事实。
2. **阅读与练习**：从案例进入研习、实验并返回，案例/知识点上下文正确；旧记录可读取、保存、恢复、导出；不同案例数据不串用。
3. **教师与交流**：虚构账号端到端验证提问、回答、引用授权、任务提交、反馈、修订；匿名拒绝、跨组拒绝、未提交草稿不可见、撤权生效，管理行为有审计。
4. **账号**：隔离数据覆盖一次性激活、并发兑换、过期、重签、旧会话失效、已激活账号不被覆盖、恢复流程和原身份/记录保持；不使用真实学生账号做破坏性测试。
5. **场景**：未开放时提示正确；预览完整体验、脚本版本不可覆盖、旧进度可恢复；正式开放前留存审阅与发布记录。
6. **质量**：干净安装后 `npm run check`、服务测试和浏览器测试通过；测试隔离真实库，浏览器覆盖桌面/手机、键盘导航和现有导出。CI 对应运行实际所需构建与浏览器安全测试。
7. **发布**：预览与正式库分离；核对迁移、备份/恢复演练、健康接口、权限及关键学习路径。提交和部署按当前用户授权及实际配置执行；涉及账号切换、真实人员或未审场景时先完成独立准备并落实必要决定。
8. **无障碍与内容**：手机 375px 和桌面视口无横向溢出；键盘可操作、表单有标签；已公开的关联全部具备可定位证据，来源疑点仍显著提示。

## 10. 决策与外部依赖

- 激活码由谁通过什么可信渠道发给学生、切换窗口和找回身份方式：实施凭据发放与生产切换前确定。

- 课堂知识图谱遮挡节点、概念口径及首批案例关联：由教师或内容负责人核定；不以图片自动转录或模型推断代替。
