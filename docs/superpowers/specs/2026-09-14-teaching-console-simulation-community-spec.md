## 1. 目标与范围

### 1.1 已确认的产品约束

本平台独立运营，以法理学学习为核心。提供适度的课程教学路径，由平台维护者管理；不是学校身份或教务系统的延伸，不承担正式课程成绩。

本轮三个核心交付：

- **P1：教师工作台和管理员后台**——真实身份、数据权限、学习小组、任务、学生提交、点评、修订、查询和导出。
- **P2：场景化仿真实验**——一个可以完整体验、提交并由教师查看产出的示范场景。
- **P3：交流专区**——提问、回答、追问、教师及实务导师参与、关联学习材料和必要管理。

学生学号清单尚未提供，批量预设账号和导入工具后置。用户提出的“学号／工号作为账号、编号后六位作为初始密码”只记录为后续账号批次的输入条件，本轮不据此生成虚构人员或弱口令演示账号。资料专区待用户提供本地材料后另行实施；本轮不增加空资料栏目。

### 1.2 本轮必须包含的配套工作

后台的基础身份认证、用户数据归属、服务端持久化和访问控制不可后置，否则不能称为可用后台。允许在开发／测试环境建立标明测试用途的管理员、教师、导师和学生账号；正式环境只接受真实维护者提供的少量初始账号，不等待整批学号清单。

不将“登录后切换角色的演示页面”“浏览器里的假数据面板”“点击按钮即完成的场景动画”计入验收。

### 1.3 明确后置

- 学生学号清单批量导入及整批账号激活。
- 资料专区、本地经验贴盘点与上传。
- 多人同步3D空间、语音房间、实时庭审调度。
- 自动生成式角色回答、AI评分和无依据的能力画像。
- 通用拖拽场景编辑器、全库在线内容管理系统。

- `lib/local-record.js`、`lib/experiment-archive.js` 将学习记录保存于浏览器；尚无云端用户归属。
- 已有完成条件、初稿、反思、版本、导入恢复和来源核验逻辑。
- 基线最后记录为177项核心测试、32项浏览器测试、584个静态入口。这些是历史验证结果，开工须重新实测，不要求机械维持测试或页面数量。

继续保留旧课程、案例ID、原文引用、六模块入口、匿名自主学习与现有JSON导出。匿名记录不自动成为课程提交。旧页面地址不能因后台建设而失效。

## 3. 技术决策

### 3.1 默认落地方式

保留现有静态前端与Cloudflare Pages，新增同域 `/api/*` 的 **Pages Functions + D1数据库**。采用仓库根目录 `functions/` 路由方式，不同时引入 `_worker.js` 高级模式。

原因：保留已运行的静态页面，同时让账号、权限、论坛、任务和档案拥有真实服务端；同域请求减少独立API域名的会话配置负担。

- 前端：沿用React/JavaScript和现有CSS，按功能增加组件，不重写全站。
- 服务端：`functions/api/` 只做HTTP适配；业务规则在 `server/`，不得被客户端导入。
- 数据：D1，SQL迁移和预编译参数查询；第一版不额外引入ORM。
- 文件：示范场景资源与现有PDF继续版本化入库。论坛第一版不收附件，暂不要求对象存储。
- 页面：静态壳 + 登录后按权限请求数据；禁止将私有数据写入静态HTML、客户端打包文件或 `public/`。
- 私有API返回 `Cache-Control: no-store`。未登录或服务端故障时不回退为模拟数据。

官方实现依据：

- [Pages Functions目录与构建规则](https://developers.cloudflare.com/pages/functions/get-started/)
- [D1等资源绑定](https://developers.cloudflare.com/pages/functions/bindings/)
- [Pages配置及已有配置读取](https://developers.cloudflare.com/pages/functions/wrangler-configuration/)
- [函数路由范围](https://developers.cloudflare.com/pages/functions/routing/)

### 3.2 环境与部署门槛

开发、预览、正式使用独立数据库。开发使用Wrangler本地运行时，测试数据只进入本地／隔离测试库。实际依赖版本在开工时选定并锁入lockfile。

新增 `wrangler.jsonc` 前读取当前Pages配置，保留既有构建设置；只对 `/api/*` 调用Functions，验证非API的静态页面与PDF仍正常服务。

正式部署前必须实际具备：Cloudflare项目操作权限、数据库绑定、迁移完成、至少一个维护者账号。缺失时可以完成本地开发与隔离环境验收，但不得以静态页面构建成功宣称服务上线。

不得假定现有 `npm start` 静态预览支持API。保留此命令预览旧内容；新增 `dev:full`／`preview:full` 等脚本运行前端构建与Pages Functions，具体端口在实现中固定并写入维护文档。

## 4. 身份与权限契约

### 4.1 身份

`student`、`teacher`、`mentor`、`admin`。用户可以拥有多个角色，服务端从数据库判定，前端不能通过请求参数指定角色。

教师与管理员可以拥有不同工作台；切换工作台不是切换身份，也不会增加权限。学生、实务导师权限即使尚无真实账号，也必须在本地测试中验证。

初始管理员通过仅限维护环境运行的一次性命令建立，不提供公开初始化URL；账号、密码和数据库凭据不进入Git。后台支持少量账号创建、停用、重置凭据与角色调整，暂不做名单批量导入。

使用成熟、适配运行时的密码哈希实现，保存算法参数与随机盐；禁止自制密码算法或明文存储。会话使用安全随机令牌，数据库只存其摘要；HttpOnly Cookie，正式环境Secure、SameSite=Lax。默认闲置2小时或绝对24小时过期，以先到者为准，可配置。

登录错误使用统一提示；对连续失败做服务端限速。退出、停用、重置密码撤销相应会话。写请求验证来源及CSRF令牌。会话恢复完成前私有输入不得开放，避免用户首次输入被迟到数据覆盖。

### 4.2 数据权限矩阵

| 对象／操作 | 学生 | 任课教师 | 实务导师 | 管理员 |
|---|---|---|---|---|
| 本人私人草稿 | 本人读写 | 不能读取他人私人草稿 | 不能读取 | 管理API不提供任意浏览私人草稿功能 |
| 小组成员名单 | 本人所属关系，非完整人员隐私 | 所负责小组 | 只显示授权任务所需显示名 | 管理全部小组与授权 |
| 任务发布／编辑 | 无 | 所负责小组 | 无 | 可管理并记录操作 |
| 课程提交 | 读写本人新版本 | 查看负责小组的提交 | 查看被明确授权任务的提交 | 查看提交范围内数据并记录敏感查询／导出 |
| 教学点评 | 阅读本人反馈 | 所负责任务 | 被授权的任务 | 可管理，不冒充教师发表评论 |
| 数据导出 | 本人档案 | 负责小组的已提交数据 | 第一版不提供批量导出 | 授权范围内，记录导出 |
| 交流读写 | 可见分区内 | 可见分区内 | 可见或受邀分区内 | 全站治理 |
| 账号／角色管理 | 无 | 无 | 无 | 允许；不得停用最后一个有效管理员或移除其管理员角色 |

所有详情、搜索、统计、导出和写入请求均复用服务端权限规则，不能只有列表过滤。越权访问不存在或无权获知的资源返回404；已知资源上的禁止操作返回403。不允许通过修改URL或资源ID跨小组读取。

撤销教师／导师授权后，新请求立即失去访问权；导出生成前再次检查权限。历史点评保留作者及当时身份，但不因此保留读取学生新数据的权限。

## 6. 教学任务与学习记录

### 6.1 模型

课程资源继续使用原course slug；教学小组是独立对象。同一课程资源可以被多个小组引用。第一版任务指定一篇案例与一个实验模块，或指定一个场景；不引入通用工作流编排器。

任务包含：标题、目标、目标小组、课程关联（可选）、caseId/moduleId或sceneId、产出要求、评价检查点、截止时间（可选）、发布版本、状态。

状态：`draft → published → archived`。草稿只有负责教师／管理员可见。发布后更改任务要求创建新版本，已开始的学习实例绑定原版本；版本更新不自动作废已提交内容。第一版不支持把正在进行的实例强制迁移到新要求。

归档任务不接受新的开始和提交，既有提交与点评仍按权限可读。无截止时间不显示逾期；有截止时间时第一版允许补交，并标为迟交，不做自动扣分。

### 6.2 提交与点评

- 私人草稿：仅本人可读写，可跨设备恢复。
- `submitted`：保存不可变提交快照，指明任务版本、学习实例、作者与服务端时间。
- `changes_requested`：教师填写具体修改意见。
- 学生修改工作稿后再提交，创建新快照，不覆盖旧稿。
- `reviewed`：教师填写检查点反馈与总结，无正式分数／成绩单。

结构齐备、学生自评、教师已阅三种状态分别展示。继续复用 `lib/experiment-completion.js`、修订与引用检查规则；后端同样校验，不能接受客户端自报 `completed:true`。

第一版不把“打开页面、观看视频、鼠标停留、点击次数”转换成能力评价。后台只展示有实际来源的任务状态、提交内容、修订次数与点评。

### 6.3 数据保存与并发

草稿写入携带服务器版本 `revision`；过期版本写入返回409并保留本地内容，提供“查看服务器版本／导出当前稿”操作，不静默采用最后写入者。

提交、再提交使用 `Idempotency-Key`，双击或网络重试只能创建一次提交。任务状态验证、提交快照、状态变化和必要通知必须保证一致；失败时不能出现半份成功记录。

客户端缓存键必须含稳定userId。退出后隐藏私有界面并移除会话相关私有缓存；存在未同步内容时先提示保存或导出，不能在退出时静默丢弃。切换账号不加载上个账号的数据。

旧 `public-showcase` 记录保持原样；登录后提供一次可重复进入的“预览并选择导入”流程。不自动认领公用设备上的历史记录，不依据旧浏览器时间回填成课程正式提交。导入后的记录标为历史自主学习记录，重复导入幂等，冲突保留两份。

### 6.4 查询和导出

教师可按小组、任务、学生显示名／账号标识、提交状态筛选。每页默认20条，上限100条；查询范围先按权限约束。

第一版导出CSV：学生账号标识、显示名、任务、任务版本、提交状态、提交时间、当前点评状态、修订次数。全文作答通过授权详情页读取，不默认批量导出。CSV对公式型前缀安全转义。

导出记录操作者、范围、行数、时间与结果；不将全文作答或凭据写入日志。导出的是查询时快照，界面说明时间范围与口径。测试包含导出越权、撤权和中文内容。

## 7. 管理员后台

必须完成：

- 账号搜索、少量创建、停用、重置凭据、角色管理。
- 小组与教师关系维护；导师按任务授权，可设置到期时间。
- 查看教学任务及场景发布状态，归档任务，不静默修改教师提交或学生作答。
- 管理社区分区、举报与帖子状态。
- 查看敏感操作日志及必要数据导出。

账号停用、授权调整、内容隐藏等操作显示具体对象与影响，完成后回读结果。删除第一版采用归档／停用，不提供一键清空学习数据。角色变更、密码重置不得通过前端直接写库。

不建设在线SQL控制台、任意文件浏览、通用数据库编辑器或可由普通教师访问的全站后台。

## 8. 场景化仿真实验

### 8.1 首个场景定义

本spec选定的默认开发样例：`campus-hearing`，标题“校园人脸识别门禁听证”，明确标为教学假设情境。这是便于实施的场景设计选择，并非用户已指定的题材。

学习目标：识别权利义务与价值冲突、区分事实与理由、提出替代方案、回应异议、解释修订依据。脚本不得冒充真实裁判、现行法的确定适用结论或教师已审定意见。

第一版采用场景化二维／2.5D表现：听证室背景、角色位置、材料桌、人物发言、证据卡和推进节点。提供明确的空间关系与任务上下文，不仅把表单放在背景图上。3D引擎、自由移动和模型采购不作为本轮必选项。

### 8.2 角色与节点

参与者选择学生代表或管理方案代表；主持人、技术服务方和其他立场按审阅后的静态脚本回应。不同角色至少在任务目标、可用立场材料和回应提示上有实质差异。角色切换须开启新实例或明确重启，不沿用原角色的提交。

| 节点 | 场景交互 | 必须留下的产出 |
|---|---|---|
| N1 接受任务 | 选择角色，了解情境与目标 | 角色、场景版本 |
| N2 阅读材料 | 打开规则草案、使用说明、各方陈述等材料 | 选择相关材料，并标记至少一处需要进一步确认的信息 |
| N3 识别争点 | 在问题板整理不同立场 | 一个争点、至少两项相冲突的考虑及说明 |
| N4 初步意见 | 向主持人陈述方案 | 初稿方案、理由、至少一条材料关联 |
| N5 回应异议 | 展示针对角色的预设质疑 | 回应一项实质异议、讨论一个替代方案 |
| N6 修订反思 | 回看初稿和材料，形成最终意见 | 当前方案、修改或保留理由、反思 |
| N7 归档／提交 | 查看学习过程，提交课程任务或自主归档 | 绑定版本的完整快照 |

点击材料只表示已打开，不表示理解。推进判断基于明确的结构化产出要求，不基于停留秒数或选中某个“正确答案”。不因学生选择某一价值优先而自动判错。

### 8.3 模式与恢复

“场景模式”和“标准模式”使用同一个状态机、数据模型、完成检查。标准模式以顺序文本、角色发言与材料列表呈现同一任务，不省略证据与质疑环节。

支持375px及以上布局、触屏、键盘操作；关键交互均有文字标签，不依赖拖拽或声音。声音不自动播放，动效可关闭。场景素材加载失败时显示可恢复提示并切换标准模式，不能丢失产出。

刷新或换设备恢复当前实例节点与已保存内容。客户端跳改节点编号、伪造材料ID或使用与实例绑定不一致的脚本版本不得生成有效提交；绑定旧版本的实例仍按该旧版本校验。

### 8.4 来源与版本

`content/scenes/campus-hearing.json` 保存场景说明、角色、节点、材料、引用与检查点；资源文件需有来源／授权记录。

发布版本使用内容指纹；已开始实例固定版本。旧版本需继续可读，不能仅覆盖当前JSON导致旧实例无法恢复。代码仓库存档不可变脚本版本，并在部署迁移时同步至服务端版本表；提交保存引用快照。

上线门槛：脚本及引用已核对、虚构部分已标明、两个角色均能走完、标准模式等价、教师能查看产出。本轮不宣称完成对学生法律观点的客观自动评分。

## 9. 交流专区

### 9.1 分区与可见性

预置“法理学答疑”“案例与实验讨论”“学习交流”三个全平台已登录用户分区；支持附属小组的课程讨论。第一版不开放匿名发帖或公开检索私有讨论。

全平台区对有效登录账号可见；小组区只对成员、任课教师、明确受邀导师与管理员可见。资源引用不能扩大原资源权限。帖子作者移出小组后不继续查看该私有讨论，历史内容与署名按治理规则保留。

### 9.2 内容与交互

- 问题：标题、分区、正文、可选课程／案例／实验关联。
- 回答：正文，可回复问题或对一个回答追问；第一版最多两层，不做无限嵌套。
- 关联现有材料时附稳定ID与链接；发布本人作答摘录必须主动选择，不自动公开学习档案。
- 使用纯文本编辑器，支持换行；不接收原始HTML、附件或外链嵌入。已有原文引用仍使用受控链接。
- 学生、教师、实务导师身份来自服务端角色，不由昵称决定。
- “有帮助”每用户每回答一票，支持撤销；不允许对自己投票。
- 教师可对自己负责的课程讨论标为精选；全平台置顶由管理员管理。精选只代表教学参考，不是唯一标准答案。
- 问题／回答可编辑并标注编辑时间；删除显示占位，避免追问失去上下文。管理员隐藏优先于作者修改，作者不能靠编辑恢复已隐藏内容。

建议校验上限：标题5—100字符，问题正文10—5000字符，回答／追问2—3000字符；仅限制输入规模，不据字数评价学习质量。

### 9.3 通知与治理

站内通知：问题获得回答、本人回答被追问、任务收到教师反馈。去重、已读、分页；只发送关联摘要，读取时再次检查权限。第一版不发邮件或短信，不做全站广播轰炸。

举报填写类型和说明，管理员可隐藏、恢复、锁定讨论，并记录原因。锁定阻止新增回答，保留已发布内容。帖子可见性变化后搜索、通知和关联列表同步遵循权限，不泄漏标题与摘要。

服务端限制登录／发帖／回复频率，限流返回429并保留输入。默认试验值可在开发配置中调整：发帖每用户每分钟3次、回复10次；不把该值当作已验证生产容量。

## 10. 数据结构最低要求

全部业务表使用服务端生成的稳定ID与UTC时间。下表给出必须包含的对象；字段可按实现补充，但不能把所有对象塞入一个用户JSON大字段。

| 表／对象 | 关键字段与关系 |
|---|---|
| users / user_roles | id、唯一login_id、display_name、状态、凭据摘要；角色独立关联 |
| sessions | token摘要、user_id、创建／活动／到期／撤销时间 |
| groups / group_members | 名称、课程slug可选；组内student/teacher身份，唯一(group_id,user_id) |
| mentor_assignments | mentor_id、task_id、到期／撤销时间 |
| tasks / task_versions | group_id、状态、current_version；每版目标与要求不可变 |
| learning_attempts / drafts | user_id、task_version可选、case/module或scene版本、revision、结构化工作稿 |
| submissions | attempt_id、递增提交序号、不可变快照、服务端提交时间、状态；幂等键唯一 |
| reviews | submission_id、reviewer_id、检查点反馈、总结、动作、创建时间 |
| scene_versions | scene_id、version、不可变脚本JSON及指纹 |
| boards / topics / replies | 可见范围与group_id；作者、内容、关联资源、状态、编辑时间 |
| helpful_votes | user_id、reply_id，联合唯一 |
| reports / moderation_actions | 举报目标、说明、状态、处理者与处理原因 |
| notifications | 接收者、事件去重键、目标ID、读取状态 |
| audit_events | 操作者、动作、资源范围、结果、时间；不得存密码或全文学习内容 |
| import_receipts | user_id、来源内容指纹、结果引用；支持历史导入幂等 |

外键、必要唯一约束和状态约束必须落实迁移。论坛列表、任务列表、学生提交查询按权限字段和排序字段建索引。逻辑删除对象不能形成公开悬空引用。

## 11. API契约

以下路径为默认接口边界。具体字段通过JSON Schema或等效验证明确，所有用户输入在服务端校验。

| 路径族 | 操作 |
|---|---|
| `/api/auth/login`、`logout`、`me` | 登录、退出、读取真实会话；其余私有API先验证会话 |
| `/api/admin/users`、`users/:id` | 列表、创建、停用、重置及角色调整 |
| `/api/groups`、`groups/:id/members` | 小组读取／创建、成员关系维护 |
| `/api/tasks`、`tasks/:id`、`tasks/:id/publish` | 任务草稿、发布版本和归档 |
| `/api/tasks/:id/mentors` | 任课教师／管理员管理该任务导师授权 |
| `/api/attempts`、`attempts/:id/draft` | 创建学习实例、恢复与带revision保存 |
| `/api/attempts/:id/submissions` | 幂等提交／再提交；只接受服务端检查通过的数据 |
| `/api/submissions/:id`、`submissions/:id/reviews` | 读取授权提交、点评与要求修订 |
| `/api/learning/import/preview`、`import/commit` | 旧记录预览与幂等认领；执行时复验 |
| `/api/exports/submissions` | 受控CSV导出与审计 |
| `/api/scenes`、`scenes/:id/versions/:version` | 列表、获取可访问的固定版本 |
| `/api/admin/scenes/:id/publication` | 发布／撤下已验证的脚本版本；不能提交任意未验证脚本 |
| `/api/boards`、`topics`、`topics/:id` | 可见分区／主题查询、创建和修改 |
| `/api/topics/:id/replies`、`replies/:id`、`replies/:id/helpful` | 回答、追问、编辑、删除和投票 |
| `/api/reports`、`/api/admin/reports`、`/api/admin/moderation` | 举报、查询和处理 |
| `/api/notifications`、`notifications/:id/read` | 站内通知及已读 |
| `/api/admin/audit` | 受控读取审计记录 |

JSON成功响应使用 `{data, meta?}`；错误使用 `{error:{code,message,requestId,fields?}}`。约定400输入错误、401未登录、403禁止操作、404不可见／不存在、409版本冲突、429限流、503服务暂不可用。不得返回堆栈、SQL或凭据。

列表返回有稳定排序的分页元数据。创建对象返回201。修改字段白名单禁止用户注入role、ownerId、completed或审核身份。账号ID从会话获取，不接受客户端声明“我是谁”。

## 12. 文件范围与代码组织

建议新增：

- `functions/api/`：路由和认证中间件。

- `migrations/`：版本化数据库迁移；`scripts/`：本地初始化、维护者初始化和测试准备。

不顺手重构全站CSS，不修改既有案例内容来适配场景，不清理用户原有未跟踪计划文件。

## 16. 上线、回退与交接

上线前：备份目标数据库；核对迁移版本；先在预览环境验证API与静态页面；初始化真实维护者；检查私有接口缓存和访问范围；核对没有测试账号、测试帖子或凭据进入正式环境。

数据库迁移优先增量且兼容上一版。回退应用前确认上一版能读取当前表结构；必要时保留兼容接口或临时停止写入，不直接删除新增数据。恢复数据库只在隔离环境演练，不用回滚覆盖发布后用户的新提交。

交接更新 `PROGRESS.md`、`CLAUDE.md`、`CONTENT_MAINTENANCE.md` 与使用指南，记录真实实现范围、命令、部署绑定、验证证据、备份恢复步骤和未完成项。内容维护文档只记录配置名称与位置，不记凭据。
