## 二、试用老师的反馈与核实结论

| 反馈 | 核实结论 | 应对方向 |
|---|---|---|
| 1. 内容庞杂、偏超前，大量部门法内容，与大一知识点不匹配 | 属实。210 个案例中民事 139、行政 37、刑事 19、执行 12、国家赔偿 3，导读和任务多从部门法角度提问 | 换成法理学视角提问：同一个案子，问“体现了什么法理问题”而不是“适用哪条法律”。建立难度分级 |
| 2. 案例与课堂知识点脱节，教师不便联动 | 属实。平台已有“法理知识点标签”，但尚未与教材章节、教学进度对应 | 和任课老师共同制作“法理学章节 × 案例”对照表，每章精选 2—3 个案例 |
| 3. 写完三步后没有自动显示判决原文；初始只有摘要 | 属实，属设计问题，不是后台故障。写完后解锁的只是参考要点，其中前两步与左栏已有内容重复；完整 PDF 一直在“原文 PDF”标签里，但默认不显示，不易发现；写完后页面仍提示“将开放对照”，承诺没有兑现 | 研读页直接提供判决全文；删去未兑现的提示；把 PDF 转成分段网页全文（已验证 210 份中 209 份可转换） |
| 4. 题目可复制粘贴到外部 AI 获取答案 | 技术上无法根本阻止（截图、拍照、手打都能绕过），禁止复制还会妨碍正常引用 | 定位为课后、不计分练习，作弊动机较低；需要考核时放在课堂或限时完成；看过程（初稿、修改稿、反思）；集中讲评时当面说理由 |

另外核实到：**平台目前不能统计视频观看时长和人数**。建议把八期课程视频放到超星，利用其任务点和观看统计；平台保留视频链接即可。

老师的使用计划（课后作业 + 集中讲评、期末复习集中研读）与平台定位一致，本学期可按此执行。

## 三、学习链路

### 核心思路

以前的网站是按**内容类型**组织的：案例、视频、实验各占一个栏目，学生不知道从哪里开始。新思路是按**学习任务**组织：**选一个案子，把它研读透、办完它**。课程、案例库、实验都退到“资料”的位置，需要时再调用。

### 三级台阶

“高阶训练”是终点，不是门槛。大多数学生从第一级开始，能力强的可以直接挑战第三级。

| 台阶 | 学生做什么 | 与现有内容的关系 |
|---|---|---|
| 一、研读 | 通读判决全文，找出争议焦点，标出“本院认为”中的推理步骤 | 落实院长“全文放上去”的建议 |
| 二、分析 | 从法理学视角写三步分析（事实—争点—法理），再与判决原文对照 | 改造现有三步研习 |
| 三、办案 | 扮演法官进入仿真庭审，写出“本院认为”，与真实判决结构化对照 | 项目负责人设想的完整链路 |

### 适应“课后·辅助”定位的四条原则

1. **平台自己给反馈。** 课后没有老师在场，学生写完需要知道差在哪里。AI 暂缓后，反馈依靠以下三样：
   - 与真实判决的**结构化对照**：争点归纳、事实认定、法律依据、结论、说理强弱逐项比较；
   - **量规自查清单**：已有 8 份量规，改写成学生能逐条勾选的自查项；
   - **交流区提问**：由老师、导师和同学回答（见第五节）。
2. **可以分段完成。** 每个案子拆成若干 20—30 分钟的小关卡，随时保存，下次接着做。
3. **入口和课堂对齐。** 每个案子标明“学完第几章后可做”，以及对应的法理学知识点。
4. **对照是对话，不是对答案。** 法院判决不等于唯一正确答案；对照后留一个问题：“你是否仍然坚持自己的某个判断？理由是什么？”

## 四、研习包（第三级“办案”的内容单元）

一个案子做成一个研习包，包含：

| 组成 | 内容 | 现有可复用的素材 |
|---|---|---|
| 卷宗 | 去掉法院结论的案件材料：双方主张、证据、争议 | 需要重新整理，这是主要的制作成本 |
| 仿真 | 以法官身份经历庭审各环节；原先六个实验作为各环节的“技能关卡”穿插其中 | 六个实验模块；“校园人脸识别听证”场景可作为形式参考 |
| 写作 | 先写“本院认为”，熟练后再写全文 | 现有写作与保存功能 |
| 对照 | 提交后解锁真实判决，结构化比较并写反思 | 8 份量规 |
| 微课 | 卡住时跳到对应的视频片段 | 现有课程视频加章节时间点，不必重录 |
| 讨论 | 交流区中该案的专属讨论 | 交流区已支持帖子关联到具体案例 |

六个实验与办案环节的对应：

| 办案环节 | 对应的实验 |
|---|---|
| 归纳争点 | 争点拆解 |
| 寻找依据 | 规范检索 |
| 理解条文 | 法律解释 |
| 写说理 | 推理构建、价值衡量 |
| 研读真实判决 | 文书批注 |

**制作范围**：每个研习包都要有法学背景的人逐案整理卷宗并由教师把关，不可能也不需要覆盖全部 210 个案例。建议先做 1 个样板，跑通后按八期主案例扩展到 8 个；其余案例继续作为研读和检索训练库。

**样板候选**：第三期的房屋买卖案（案例 0012）。它的核心争议是合同中“按第 2 种方式处理”与条款序号“(2)”冲突时如何理解，正好对应法理学中的法律解释方法，大一学生也能进入。

**角色**：第一版只做法官，因为法官的产出可以直接与判决对照。律师、检察官的产出（代理词、公诉意见）需要另一种对照方式，即“法院是否采纳了你的观点，为什么”，放到后续版本。

## 五、交流专区

- **可行，而且已经做好**，只是尚未正式上线。GitHub 只存放代码，网站实际运行在 Cloudflare 上，Cloudflare 自带数据库，可以保存账号和帖子。
- 已有功能：提问、回答、追问、投票、举报、隐藏和锁定、通知、导师邀请，帖子可关联到案例、实验或场景。
- AI 助教暂缓后，交流区是学生课后提问的主要渠道，作用更重要了。
- 上线前需要：
  - 完成技术整改方案中的三项前置工作：确认线上状态、更换可推导的初始密码、实测登录性能；
  - 确定由谁日常查看和回复；
  - 实测国内访问是否稳定（`pages.dev` 域名在国内访问可能不稳定，需找学生用校园网和手机流量测试）。

## 六、3D 仿真

- **技术上可以实现**，在浏览器中运行，托管在 Cloudflare 上也没有问题。
- **主要成本在美术和适配**：法庭场景、人物、动作需要 3D 美术制作或购买授权素材；素材文件较大，要考虑学生设备和校园网的加载速度。
- **教学价值要分清**：学习效果主要来自“读材料—判断—写理由—对照”，3D 主要提供沉浸感和展示效果。
- **建议顺序**：先用 2D 插画配对话（类似视觉小说）把内容和流程跑通；验证有效后，再升级为固定视角的轻量 3D 法庭，内容可以直接复用。
- 如果将来计划申报虚拟仿真实验教学类的课程或项目，应在开发前对照当年的申报和评审要求设计。

## 七、网站结构与外观

- **两扇门**：
  - 对外是项目成果主页，给评审和来访者看；
  - 对内是学生的学习工作台，学生登录或点击“进入学习”后直接落在这里，日常使用不再经过宣传内容。
- **统一命名**：每个概念只保留一个名字。目前“课程认知／课程体系／八期课程档案”指同一栏目，“档案”一词又同时指课程和学生的学习记录，需要先统一。
- **简化导航**：场景研习归入实验；资料专区在有内容之前不出现在主导航；每个导航项使用不同的图标；左侧栏底部精简。
- **学生的学习记录合并为一处**：让学生不必区分“本机保存”和“账号保存”。
- **视觉减法**：减少卡片套卡片和边框；统一字体；只保留一种强调色；统一板块标题样式，拉开信息层级；修正深色模式下的低对比按钮。具体排版在链路确定后逐页调整。

## 八、建议的推进顺序

| 阶段 | 内容 | 回应的问题 |
|---|---|---|
| 本学期（期末前） | 研读页直接提供判决全文；删去未兑现的提示；与老师共同挑选期末复习用的案例并做章节对照；视频放到超星统计观看 | 老师反馈 1—3，院长建议 |
| 下一步 | 入门案例改为法理学视角的导读和任务；三级台阶上线；难度分级；统一命名、简化导航、成果主页与学习工作台分开；交流区完成前置工作后上线 | 老师反馈 1、2，体验盘点 |
| 然后 | 做第一个研习包样板（2D 仿真 + 写作 + 结构化对照），验证后扩展到 8 个 | 核心学习链路 |
| 后期 | 3D 场景升级；视情况对接申报要求 | 展示与申报 |
| 暂缓 | AI 助教（预算允许时再议；届时按已讨论的方案接入国内已备案模型） | —— |

## 九、待决定的事项

1. 样板研习包是否选第三期的房屋买卖案？还是另选？
2. 本学期期末复习用哪些案例？需要任课老师给出章节和进度。
3. 交流区由谁日常查看和回复？是否邀请实务导师参与？
4. 研习包的卷宗由谁整理、由谁审阅？
5. 八期课程视频是否确定迁到超星？平台上保留链接还是保留播放？
6. 案例中自然人姓名是否统一匿名化？
7. 判决书 PDF 带有“北大法宝”页眉和引证码，是否需要核实使用条款，或改用其他来源？
